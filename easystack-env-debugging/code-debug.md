# Runtime Code Debugging

## Scope And Authorization 范围与授权

用于用户明确要求在目标环境验证代码、临时覆盖或调试路径的任务. 不要求先证明存在故障,
也不强制执行完整根因调查; 先做足以选择方法、确认影响和恢复基线的最小只读检查.

前端调试默认使用项目本地 dev-server 和 proxy; 仅在用户明确要求部署验证时替换环境 dist.
后端修改默认以完整项目运行代码或匹配构建产物作为替换与回滚单元, 不用单文件或子模块
同步冒充整项目更新. 本地前端代码、环境后端代码和正式部署结果分别记录与验证.

沿用会话中仍有效且范围匹配的明确授权. 写入前必须覆盖目标环境、服务、节点/调度范围、
文件或产物、允许的变更动作、验证方式和回滚方式. 缺项或影响实质变化时补充说明并取得授权,
不逐阶段重复请求已有授权. 开发、CI 或只读测试授权本身不授权部署、覆盖、重启或缩容.

访问环境遵循 [access.md](access.md), 首项环境命令仍使用统一 `env-access.sh` 入口.
只读发现不执行传输或变更; 文件传输也须使用已授权路径, 不自行拼接登录方式、修改访问脚本
或将材料中的账号、凭据和环境地址写入通用流程.

## Baseline And Target 基线与目标

定点读取当前任务需要的事实, 记录来源和待确认项:

| 对象 | 必须确认的基线 |
|------|----------------|
| 工作负载 | 环境、namespace、项目的所有实际消费 workload/Pod/container、控制器及相关副本 |
| 版本与产物 | 确认的 revision、完整项目文件清单、构建方式、运行版本、镜像 digest 与现有覆盖 |
| 运行入口 | 真实 entrypoint、进程/worker、解释器或二进制、实际加载路径与相关启动配置 |
| 文件与挂载 | 容器有效文件、已有挂载及其源、单文件/目录/subPath 形态、权限和内容摘要 |
| 管理与调度 | Helm/operator 等实际管理源、可能收敛覆盖的配置、可运行节点和现有调度约束 |
| 恢复依据 | 完整项目有效基线、环境生成配置来源、挂载/启动/配置/副本/镜像/调度原值及备份 |

不从服务名推断 Python 版本、目录或启动命令, 不假设已有 `/opt` 或 hostPath 挂载.
同名服务、多个容器、旧 Pod 和不同副本分别核对, 不把本地分支当成当前部署版本.
运行目录可能已含历史覆盖; 导出文件前区分镜像内容、挂载和已有修改, 不称其为干净发布基线.
本地与运行版本不一致时, 先明确补丁适用性和必要依赖, 不整包覆盖掩盖版本漂移.

明确项目自身的运行代码包、所需资源及匹配产物边界, 不把仓库根、整个 `site-packages`、
解释器环境、共享依赖、配置或数据目录一起替换. 按已授权且版本兼容的消费组(cohort)
列出目标 revision、依赖和所有工作负载, 不把更新某个 Deployment 当成整个项目已更新.
不同版本组需分别核实适配与基线, 不能将同一代码包未经核对覆盖全部服务.

## Method Selection 方法选择

在上述更新单元内按实际加载、持久性和验证目标选择方法, 不将历史单文件捷径设为默认:

| 方法 | 适用前提和边界 |
|------|----------------|
| 前端本地 dev-server + proxy | 使用项目真实启动/代理配置, 证明浏览器加载本地新代码且请求到达目标后端 |
| 应用支持的 reload | 已确认目标内容支持重新加载, 并可验证所有相关 worker 已加载新版本 |
| 容器可写层临时替换 | 路径确实可写且未被其他源遮盖; 文件到达不证明进程已加载, 重建可能丢失 |
| 复用已有持久覆盖 | 支持完整项目内容及生效方式, 已处理更细粒度覆盖和启动复制优先级 |
| 新增挂载或启动阶段覆盖 | 当前部署支持且明确授权; 记录配置差异、遮盖范围和管理控制器可能的回写 |
| 构建并切换镜像 | 需要可复现产物或运行层替换不适用, 按真实构建/部署入口核对 digest 与依赖 |
| 配置变更 | 与代码、镜像分开记录管理源和加载方式, 不把改代码自动扩展为改产品配置 |

解释型服务也不能默认支持热更新; 编译型服务先生成匹配当前架构、依赖和 ABI 的产物,
不把源码复制当成二进制更新. 前端使用实际构建输出、服务根和资源前缀, 不是统一 nginx 路径.
静态文件能否立即读取与页面能否加载新版本分别验证, 不能无条件推广免重启.
环境 dist 注入仅是明确要求的部署验证路径, 不替代本地开发. 本地代理/隧道可达也不证明
加载本地 bundle; 独立 SPA 和 Host/Module Federation 接入按实际工程配置分别确认.

镜像、运行层覆盖、持久挂载和产品管理配置是不同状态. 临时路径验证不代表镜像已经包含修复;
切换镜像后仍需检查旧覆盖是否遮盖新内容. 控制器重建后是否保留变更取决于实际管理源,
不为保住临时修改擅改产品定义或关闭控制器.

## Apply And Activate 应用与生效

后端项目替换按以下顺序执行; 前端本地调试按项目已有 serve/proxy 入口进行:

1. 记录完整项目的有效基线、相关挂载/启动/配置原值及回滚清单, 保留可恢复的完整副本.
   区分源码与环境生成配置、数据和依赖, 保护既有覆盖与他人修改, 不复制凭据到调试产物.
2. 按确认 revision 和任务内改动的完整文件清单准备暂存代码包/匹配产物, 不夹带无关修改.
   核对新增、修改、删除和摘要后按授权方案切换, 仅在确认的项目运行代码/产物边界内清理过期项;
   tar 合并不会自动清除旧文件, 不能据此宣称完整替换. 不包含 `.git` 或无关开发产物.
3. 核对目录遮盖、单文件/subPath 挂载和旧启动复制的优先级, 确保实际使用完整目标项目.
   冲突覆盖必须纳入授权方案, 不越权移除旧挂载; 目录需完整兼容运行版本.
   保留环境生成配置的来源、加载顺序和目标写权限, 不以只读代码挂载阻断启动时配置生成.
   配置或依赖确需变化时按实际授权单独处理, 不通过覆盖整个解释器环境补齐.
4. 使用节点本地文件时覆盖全部可能执行目标, 或使用明确授权且已验证的调度限制.
   记录各目标摘要和同步失败项; 仅 `scale=1` 不能证明节点固定, 不默认缩容提速.
5. 必须改启动脚本时只插入已授权的必要逻辑, 保留真实启动参数、进程管理、信号处理和日志路径.
   不用示例 Python 命令替换实际 entrypoint, 不在未授权时修改副本数、调度或服务配置.
6. 对授权版本组的全部相关消费工作负载按真实加载机制执行 reload、进程/Pod 重建或
   部署更新, 核对中断与副本影响, 各组分别记录结果.
   不将容器内复制后重建作为通用持久方案, 不默认用删除 Pod 触发生效.

明确要求前端部署验证时, 替换使用真实构建目录和完整资源集合, 核对入口引用、缓存与版本.
不因某个 JS 文件含标记就认定浏览器已加载或业务验证通过; 也不擅自删除旧资源清理环境.
变更失败时停止扩大影响, 保留具体失败目标和当前状态, 按已授权恢复方案处理.

## Evidence And Verification 证据与验证

分别收集以下证据, 任何一层缺失都不能被另一层成功代替:

| 层次 | 需要的证据 |
|------|------------|
| 文件到达 | 后端各消费组完整清单及摘要一致, 增改删正确且保留环境配置; 前端核对实际构建/部署来源 |
| 运行版本 | 所有相关进程/worker 或实际页面加载目标版本, 副本一致, 无旧代码覆盖且环境配置按约定加载 |
| 目标行为 | 按本次改变的行为执行实际入口, 核对请求、状态/业务效果和调用方反馈 |

`grep`、文件摘要、Pod Ready 或 HTTP 成功只证明各自对应的部分事实.
解释器和包路径定位只证明查找位置, 不证明既有 worker 缓存已更新. 仅抽样一个 Pod 时
明确标记覆盖限制, 不推广为全部副本已加载; 本地联调另须证明 bundle/remote 来自本次开发实例.
重建后重新核对 Pod、节点、容器和有效代码, 不以旧 Pod 的证据证明新进程已加载.
按风险检查日志、异常、失败恢复和已有支持行为, 不为单纯展示文案变更新增资源操作验收.
验证命令、资源动作和破坏性场景须在授权内; 不具备执行条件时记录未验证项和影响.

本文件只负责代码生效和明确的调试路径. 完整资源回归按
[easystack-test-executor](../easystack-test-executor/SKILL.md) 的支持范围执行,
UI 验收按 [easystack-cloud-web-e2e](../easystack-cloud-web-e2e/SKILL.md),
仓库 CI 按 [easystack-ci-test](../easystack-ci-test/SKILL.md). 不自动启动全部流程,
也不将临时覆盖下的成功称为最终镜像、部署或完整回归已经通过.

## Rollback And Recovery 回滚与恢复

只撤销本次任务改变的内容, 按现场记录的原值和已授权顺序恢复:

- 将每个消费组的完整项目恢复到基线清单和权限, 恢复本次删除项并移除本次新增项目代码/产物,
  同时定点撤销本次挂载/启动变更.
  不删除原有调试挂载、共享目录或他人文件; 先确认引用解除再处理本次临时数据.
- 镜像恢复到记录的实际版本, 并核对已有覆盖; 恢复镜像并不自动恢复挂载内容.
- 恢复环境生成配置的原来源/加载方式、原配置、调度与副本数, 不硬编码副本数或借升级清理.
- 按真实加载机制使恢复生效, 再检查运行版本、相关副本、关键行为和残留变更.

容器内临时替换是否随重建恢复, 取决于实际文件来源. 挂载仍在时删除 Pod 不等于撤销覆盖;
不以命令成功或恢复请求发出作为回滚完成证据. 有意保留调试状态时记录授权、对象和后续处理,
未获额外授权或无法恢复时说明现状和剩余风险, 不宣称环境已恢复.

## Sources And Calibration 来源与校准

用户提供的 `encrypted-volume-dev-notes.md` 和 `easystack-code-injection-method.md` 记录
其他环境的历史单文件/dist 注入, 不是本轮完整项目替换已落地的证据. 被引用的全局
`easystack-dev-injection/scripts/devpush.sh` 仅 tar 合并、更新单工作负载并检查首个匹配 Pod;
目录分支没有完整项目备份, `--dry-run` 仍会远程发现节点, 不能直接继承为完整替换或离线工具.

2026-10-20 对用户本轮指定测试环境的只读校准: 8 个目标 Deployment 均配置 3 副本,
仅对其中 6 个后端工作负载各抽样 1 个 Running Pod, 未对两个前端目标抽样 exec.
后端包定位为 Cinder/Python 3.9、golem/Python 3.6;
API/scheduler/openstack golem 未见 `/opt` 挂载, volume/backup/thor golem 有 `/opt`,
未见历史笔记的 esfix/debug 项目文件挂载, 不能按旧路径直接同步.
openstack golem 启动会将环境文件复制为项目内 `golem/api/v3/settings.py`, thor golem 则
直接启动 `golem-api`; 完整替换须分别保留配置生成、写权限与加载顺序.
这些是限定样本, 不证明所有 worker 的缓存或功能已更新, 也不固定通用语言、目录或副本数.

## Result Report 调试结果

纯代码调试精简报告, 不套用根因调查的第 1 至第 4 节模板:

1. 授权范围: 环境、服务、执行目标、文件/产物和允许的动作.
2. 调试基线: revision、完整项目边界/清单、消费版本组、运行版本和挂载/启动/配置恢复依据.
3. 实际改动: 本地前端或后端替换方法、产物摘要、配置与重建影响, 各目标成功/失败状态.
4. 验证结果: 文件、运行版本和相关行为的实际证据, 失败、未执行项及限制.
5. 回滚状态: 恢复基线、实际执行结果或保留状态, 当前残留对象和风险.
6. 后续动作: 必要的资源回归、UI、CI 或正式部署缺口, 不自动推导交付授权.

同时需要故障根因判断时, 另按 [report-format.md](report-format.md) 输出有证据的问题调查,
再附上述调试记录. 凭据、用户数据和无关环境信息必须脱敏.
