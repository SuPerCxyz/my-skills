# Skill Evaluation

这组通用 prompt 用于检查现有 12 个 Skill 的正负触发、用户点名、阶段重选和已加载
内容去重, 并补充 workflow 的 CI recheck 证据、授权、版本、去重与结果场景。结构沿用已有 eval 的 `prompt`、`expected_output`、`expectations`, 不附带
平台 runner、固定模型或客户端配置。

## Files 文件说明

| 文件 | 用途 |
|------|------|
| [cases.json](cases.json) | 12 个 Skill 各一组正例/近邻负例, 加 3 个会话行为及 9 个 CI recheck 离线语义场景 |
| [../../easystack-test-executor/evals/README.md](../../easystack-test-executor/evals/README.md) | 现有领域 eval 的定义与真实输出校验说明 |

## Evaluation 评估方法

1. 先确认待评 Skill revision 和平台实际提供的目录, 不把目录存在当作正文已加载。
2. 正负例成对使用, 记录每例的前置状态。新会话与恢复会话分开; context 的负例明确
   是同一会话已加载且未变化, 不是否定 session-start 触发。
3. 若以后获准执行真实模型评估, 在独立上下文中对比有 Skill 与无 Skill 的基线;
   评估既有 Skill 修改时, 对比修改后版本与修改前版本。两组使用同一模型/配置和
   同一 prompt, 不让已加载的规则泄入基线; 每例至少重复 3 次, 保存脱敏完整输出和
   工具轨迹, 再逐条语义评分。不要用关键词命中代替评分。
4. 记录是否选择正确 Skill、是否实际读取正文、是否在相关操作前加载、是否遵守边界、
   是否误触发或重复读取。用户点名不取消实际授权门禁; 多 Skill 匹配时只读取本次必要者。
5. 真实结果报告分母、重复次数、失败例和环境限制, 不将少量结果推广为稳定 100% 调用。

## Validation Levels 验证层次

| 层次 | 可以证明 | 不能证明 |
|------|----------|----------|
| JSON/元数据/内链检查 | 场景结构和引用一致 | 模型会选中或遵守 Skill |
| 命令与行为 fixture | 对应脚本/文档示例在给定输入下的行为 | 真实环境业务效果或模型触发率 |
| 获准的真实模型评估 | 指定配置和样本的实际调用/遵循情况 | 所有模型、平台和任务的普遍保证 |

本轮只检查前两层, 没有运行真实模型, 不填写虚构调用率、benchmark 或 grading。
通用 Skill 提供可发现的触发说明和执行规则, 不能强制宿主客户端调用。
