# EasyStack Runtime Debugging

## Scope And Access 范围与访问

本文件独立提供在线故障调查、已授权运行代码调试和离线 `.eslog` / `ecs.*` 分析流程.
代码路径验证不要求先证明存在故障; 只读故障调查不自动扩大为代码修改或部署.
使用用户提供的已授权入口及当前平台实际可用的 Shell、SSH、kubectl、API 和归档工具,
先确认真实连接配置和命令能力. 已安装的专用调试或日志 skill 仅作可选增强,
不要求其他 skill、固定脚本、环境目录或工具安装. 缺少工具或入口时说明缺项及影响,
继续不依赖它的安全检查; 不自动安装、修改环境或编造连接方式.

发现和诊断默认只读. 写入前授权须覆盖目标环境、服务、节点/调度范围、文件或产物、
允许动作、影响、验证和回滚方式. 已有范围匹配授权可沿用; 修改代码的授权不自动授权
环境覆盖、重启、缩容、配置或数据写入. 保护他人修改、已有挂载和共享数据,
访问及证据均不得泄露密码、Token、Cookie、私钥或用户敏感数据.

## Online Investigation 在线调查

1. 明确现象、资源名称和完整 UUID、故障时间窗及其时区、目标环境和已知版本.
   先发现相关工作负载和日志目标, 再读业务 Pod 当前日志, 不以大批资源状态查询代替
   日志调查. 按实际支持的时间参数限制输入, 对 UUID/request ID 检索先过滤再限制输出.
2. 当前日志不覆盖事件时查询可用的集中/历史日志, 重启场景补 previous 日志.
   不猜测 fluentd 文件路径或默认采集完整. 状态查询用于补关联、租户、执行节点与终态,
   当前状态不能证明历史操作如何发生.
3. 从 request ID、资源 UUID 和操作时间定位主服务, 沿真实调用追查 worker、RPC、
   调度及关联资源. 需要时解析云主机 UUID 到 libvirt domain、云硬盘 UUID 到
   attachment、设备、WWID/IQN 或 RBD 标识的映射, 不从名字猜测底层对象.
4. 只有日志出现相应信号时才扩展到节点、存储、网络、Ceph、RabbitMQ、MariaDB
   或时钟配置; 人工操作线索出现时才查对应窗口的操作记录, 不无条件扫描所有域.
5. 找到关键操作、状态变化、直接失败和触发机制时立即保留原文、时间、来源、关联键
   和必要上下文. 只有实际运行版本、配置、代码或外部依赖证据能连接因果链时才确认根因.
   超时、上游错误、异常状态和单一堆栈不能单独当根因; 未查到异常不能证明没有问题.

系统源码深入分析仅在 kernel、驱动、系统调用、动态库或软件包有直接信号, 且定向日志
和配置不足以解释机制时进行. 记录发行版/上游版本、完整 commit、补丁状态及源码路径;
未与目标环境精确对齐的源码只作线索, 不能单独作为根因证据.

## Runtime Baseline 运行基线

代码更新前做最小只读核对, 记录完整恢复依据:

| 对象 | 必须确认的事实 |
|------|----------------|
| 代码与产物 | 确认 revision、任务内修改、完整项目运行文件清单和摘要、真实构建方式及镜像 digest |
| 消费范围 | 所有消费该项目的 workload、控制器、Pod/container、进程/worker、副本及可调度节点 |
| 真实加载 | entrypoint、解释器/二进制、包加载路径、目录/单文件/subPath 挂载、启动复制及其优先级 |
| 环境保留 | 配置生成来源、写入顺序、权限、加载方式、数据与依赖边界、已有覆盖和他人修改 |
| 管理与恢复 | Helm/operator 等管理源、可能的收敛覆盖、原镜像/挂载/启动/配置/副本/调度值及完整备份 |

以完整且版本兼容的项目运行代码或匹配构建产物作为后端更新、备份和回滚单元.
明确所需代码包和资源边界, 不盲目替换仓库根、整个 site-packages、解释器、共享依赖、
配置或数据. 本地分支不代表环境版本; 当前运行目录可能已有覆盖, 不称为干净发布基线.
按已授权且版本兼容的消费组分别记录目标版本与基线, 不将同一包未经核实覆盖所有服务.

以下是只读发现模板, 通过用户已授权的环境入口执行; 占位符须替换为现场确认值,
不是本地可直接运行的部署命令. 对每个实际消费者分别核对, 不按名称猜测控制器类型:

```bash
NS='<namespace>'; KIND='<confirmed-controller-kind>'; WORKLOAD='<name>'
SELECTOR='<confirmed-label-selector>'; POD='<current-pod>'; CONTAINER='<container>'
kubectl -n "$NS" get "$KIND" "$WORKLOAD" -o jsonpath='{.spec.selector}{"\n"}'
kubectl -n "$NS" get pods -l "$SELECTOR" -o wide
kubectl -n "$NS" get pod "$POD" -o jsonpath='{.spec.nodeName}{"\n"}{.spec.nodeSelector}{"\n"}{.spec.affinity}{"\n"}{.spec.tolerations}{"\n"}{.spec.schedulingGates}{"\n"}{.spec.topologySpreadConstraints}{"\n"}'
kubectl -n "$NS" get pod "$POD" -o jsonpath='{.spec.volumes}{"\n"}{range .spec.containers[*]}{.name}{"\t"}{.image}{"\n"}{.volumeMounts}{"\n"}{.command}{"\n"}{.args}{"\n"}{end}'
kubectl -n "$NS" exec "$POD" -c "$CONTAINER" -- ls -ld '<confirmed-project-path>'
```

从定向输出确认 volume/volumeMount、subPath、节点、镜像和启动参数; 仅路径存在
不能证明真实加载位置. 控制器字段按实际 kind 校准, 不适用时定向检查其真实模板路径;
需要时核对 init container 的启动复制逻辑及其他相关调度字段, 不读取全部 env 或凭据.
按实际运行栈继续检查进程与加载来源, 启动参数和配置中的敏感内容须脱敏.

## Apply And Activate 应用与生效

1. 保存每组完整有效基线和恢复清单, 备份可恢复性、权限及摘要可核对.
   将环境配置、数据、依赖与项目代码分开, 不把凭据复制进调试产物.
2. 从确认 revision 和本次任务内改动准备完整暂存代码/匹配产物, 对账新增、修改、删除
   和摘要. 单文件覆盖或 tar 合并不能证明整项目更新, 合并不会自动删除旧文件.
   仅在授权项目边界内处理过期项, 不夹带 `.git`、无关改动和开发产物.
3. 按真实加载机制选择已有挂载、运行层覆盖、应用支持的 reload 或匹配镜像切换.
   新增挂载、改启动或配置须在授权内. 核对目录遮盖、subPath、旧启动复制和加载顺序,
   不擅自移除冲突覆盖. 保留环境生成配置来源、写入顺序和写权限,
   不以只读代码挂载阻断启动配置生成. 依赖或配置变化单独核实授权.
4. 节点本地内容须覆盖全部可能运行节点, 或使用已明确授权且验证过的调度限制.
   覆盖该消费组全部相关副本并记录逐目标摘要和失败项; 缩为一个副本不能证明节点固定.
   不默认缩容、删除 Pod 或关闭控制器以保留临时修改.
5. 编译服务使用匹配架构、依赖与 ABI 的构建产物. 启动脚本只插入授权必要逻辑,
   保留真实参数、进程管理、信号和日志路径. 按真实机制执行授权的 reload/重建/部署,
   不能默认 Python 热更新, 也不能复制容器可写层后用重建当持久化方案.
6. 失败时停止扩大影响, 记录各目标当前状态, 按已授权方案恢复. 镜像、运行覆盖、
   持久挂载和管理配置分别对账, 临时覆盖成功不代表正式镜像含修复或发布已完成.

操作模板按下列对象串联, 每个消费组单独填写; 传输和切换使用现场已有且获授权的机制,
不假设通用远端路径、登录链或部署脚本:

```text
revision=<confirmed-revision>; project=<runtime-code-boundary>; cohort=<compatible-consumers>
baseline=<complete-effective-project-backup>; stage=<complete-target-project>
targets=<all-eligible-nodes-and-consumers>; restore=<recorded-original-state>
1. 备份 baseline 及权限/摘要, 单独记录环境配置生成来源和原挂载/启动/调度值.
2. 从 revision 和任务内改动生成 stage, 用项目文件清单逐项列出新增/修改/删除与摘要.
3. 通过已授权传输方式暂存至 targets, 对账完整清单; 不直接 tar 合并到生效目录.
4. 按下表选择切换方式, 保留环境配置及写权限, 再按真实加载机制激活全部消费者.
5. 逐目标记录文件/运行版本/行为证据; 任一失败停止扩散, 按 restore 恢复并复验.
```

| 现场状态 | 切换与恢复要求 |
|----------|----------------|
| 无持久覆盖 | 不先同步到假定 hostPath. 选择获授权的完整项目挂载、运行层替换或镜像更新; 新挂载须确认管理源、完整目录和配置生成兼容性, 保存原定义供恢复 |
| 已有目录或单文件覆盖 | 先确认有效来源及遮盖优先级. 支持完整项目的覆盖可复用; 单文件/subPath 阻挡完整项目时, 先将精确调整纳入授权, 不仅更新该单文件或擅自拆旧挂载 |
| 节点本地源及多副本 | 列出全部可能调度节点与实际消费者, 全部暂存对账后再激活; 某节点失败不继续扩大更新. 保留逐目标状态, 不以一个 Pod 成功代表全部完成 |

暂存与基线清单必须能区分代码、环境配置和已有修改, 明确删除项及恢复来源;
目录清单相同也仍需确认内容摘要、权限与真实进程加载. 不将部分成功包装为原子更新.

前端本地 dev-server + proxy 仅作开发和预验证. 前端代码修改后必须完成以下部署闭环,
无可见变化也需部署并说明实际影响, 不以本地调试替代:

- 按项目已有构建入口从本次确认源码和任务内改动生成匹配产物, 记录 revision、改动范围、
  构建结果及产物版本/摘要. 构建失败停止部署, 不拿旧包冒充本次结果.
- 核对验收环境 URL、当前版本、兼容性、实际部署入口、服务/副本范围及有效授权.
  复用匹配的既有授权; 未知目标或权限不足时报告缺口, 保留部署未完成必做项,
  暂停依赖部署并推进独立工作, 不推导任意生产、重启或配置覆盖权限.
- 复用上文基线与备份规则, 保存完整有效前端产物、部署状态和可核对的恢复依据.
  保留环境运行配置、API 地址、挂载、权限、已有覆盖与他人改动; 不能用构建默认配置
  覆盖环境配置或把凭据打进产物. 冲突无法安全保留时先报告, 不盲目覆盖.
- 使用目标项目已有部署机制发布匹配的完整构建产物, 对账新增、修改与删除及全部相关
  消费副本. 按实际机制决定生效方式, 不强制直接覆盖 dist、固定 nginx 目录或删除 Pod.
  部署失败停止扩大影响, 按预先确认的恢复方案恢复并核实状态; 无法恢复时如实报告.
- 按 [frontend-testing.md](frontend-testing.md) 核对 SPA 或 Host Remote 的实际入口、
  baseHref/资源前缀、bundle/remote/chunk、缓存与 Content-Type, 证明浏览器实际加载本次
  部署版本并访问正确 API 与会话/租户, 再验证实际业务与视觉/主题效果. 部署接口成功、
  隧道可达、HTTP 200 或文件含标记均不能代替页面生效与验收证据.

最终直接向用户提供 [product-documentation.md](product-documentation.md#required-content-必需内容)
规定的环境、版本与页面查看清单, 分开报告构建、部署和实际验收结果; 未完成不称完整交付.

## Verification And Rollback 验证与回滚

分别核实完整文件清单和增改删到达、实际进程/worker 或页面加载版本、目标业务行为.
所有相关副本、容器和消费组都需核实; 仅抽样一个 Pod 时明确覆盖缺口.
包路径、摘要、Ready、HTTP 成功均只证明局部事实, 不能证明 worker 缓存或业务已更新.
重建后重新定位新 Pod、节点及容器, 不沿用旧对象证据.
实际行为验证见 [backend-testing.md](backend-testing.md) 和
[frontend-testing.md](frontend-testing.md), 按本次范围执行, 不自动启动全部回归.
环境或授权不足时列明未执行路径、原因、替代检查与剩余风险, 不用静态检查冒充业务验收.

只撤销本次变更, 各消费组按备份恢复完整项目、权限及本次删除项, 移除本次新增代码;
恢复本次挂载、启动、镜像、配置来源/加载方式和原调度/副本值, 保留已有修改与共享目录.
先解除引用再清理本次临时物. 镜像回退不自动恢复挂载内容, 挂载仍存在时删除 Pod
不等于撤销覆盖. 按真实加载机制使恢复生效并复验运行版本、全部相关副本和关键行为.
不以恢复命令成功当作回滚完成; 有意保留调试状态须记录授权、对象和后续动作,
无法恢复时如实说明当前状态与风险.

恢复记录可按 `消费组 -> 目标节点/工作负载 -> 原完整清单/摘要/权限 -> 原管理配置 ->
恢复激活动作 -> 新 Pod/worker 版本与行为结果` 填写. 逐目标恢复本次删除项、移除本次
新增代码, 同时还原本次覆盖内容及挂载定义; 不只回滚 Deployment 或镜像就结束.

## Offline Evidence 离线证据

用户明确要求离线分析, 或历史故障超出在线日志保留窗且有本地材料时使用本流程.
单独离线任务不要求在线访问; 联合分析先建立历史证据链, 再补充有价值的当前状态.

1. 用户指定路径时仅使用该路径. 未指定时只检查当前工作目录顶层的 `.eslog` 和
   `ecs.*`, 不递归扫描目录外或把普通日志自动纳入. 未找到则报告已检查目录并索取路径.
2. 同一 bundle 优先使用经确认完整的已解压目录. 多包先用文件名采集范围匹配故障
   时间, 再用实际日志核实覆盖; 多包都覆盖时联合分析. 时间未知且无法唯一选择时询问,
   不默认选最新包. 保存 bundle、节点、解压目录与采集范围映射.
3. 需解压时先识别实际格式与可用归档能力, 检查输出路径和空间, 使用获授权的本地工具
   写入独立目录, 不覆盖原包或混合不同 bundle. 不猜测 `.eslog` 等于普通 tar/zip.
   加密密码通过安全方式提供, 不写入文档、日志或命令历史. 缺少解密/解压能力时报告
   未取得的证据, 可请求已解压材料, 不安装工具或依赖外部脚本固定路径.
4. 保留原始归档和压缩日志. 对已识别格式按需生成可搜索 `.log` 副本, 核对目标节点、
   文件和时间覆盖后停止解压; 不反复解压或用合并输出掩盖残留文件.
   证据引用原始 `ecs.*` 来源下对应日志的 `file:line`, 不以重排聚合视图替代来源.
5. 先确认日志 wrapper 中时间、节点、Pod、容器和原文的实际结构及服务时区,
   保留 raw timestamp 并归一化窗口. 有偏移按声明解析, 无偏移不得默认 UTC;
   时区未确认时明确顺序限制. 包采集时间不能替代事件时间.
6. 先按目标 UUID/request ID、时间窗和主服务目录定位, 再沿关联键扩展到实际组件.
   对匹配条件先过滤再截断输出, 保存最小充分原文和上下文, 避免整包扫描式报告.
   日志缺失、轮转、采集不全和时钟差异均列证据限制; 当前正常不能否定历史故障.

## Investigation Report 调查报告

调查报告使用标题 `问题调查报告`, 开头以自然段说明对象、关键触发操作、已验证原因和结果.
默认第 1 至第 3 节, 编号连续; 不使用表格, 章节用普通文本, 子项用 `事件 1`、`事项 1:`
等标签, 避免裸数字与章节编号冲突. 报告任何行不得以 `-`、`#` 或 `$` 开头,
原文命中时添加 `原文: ` 前缀, 保留原始内容. 命令/日志/配置使用对应语言代码块.

1. 核心结论. 依次包含问题现象、通俗说明、问题原因、问题影响和修复建议.
   通俗说明用一段串联直接现象、核心机制和最终结果. 问题原因按因果阶段分段,
   每段以具体时间/范围或 `时间待确认` 开头, 说明操作、资源、组件、状态及如何导致
   下一阶段. 修复建议一句写明对象、动作与预期结果. 未验证根因时明确
   `直接失败已确认, 根本原因未确认`, 通俗说明注明核心机制未验证, 不编造机制.
2. 关键操作时间线与证据. 每个事件包含时间、操作、资源、节点或组件、结果、来源、
   直接证据原文和证据说明. 在线注明 Pod/服务/对象/时间, 离线增加 `file:line`.
   无日志时写 `未取得对应日志`, 只用实际命令、配置或数据库只读记录补证并列明缺口.
3. 未确认项与限制. 写明客观证据缺口、访问/版本/时间窗限制和最小补证动作.
   末尾提示可按需继续输出详细分析. 仅用户明确要求完整上下文、审计或复核时增加
   第 4 节详细分析, 与第 2 节事件逐点对应, 不编造缺失上下文.

首次出现资源使用显示名称和完整 UUID, 名称缺失明确注明; 使用云主机、云硬盘称谓,
节点设备附实际设备名, 命令和日志原文技术标识不改写. 结论逐项对应本次直接证据,
限定环境、版本、配置、对象和时间窗, 不输出无证据假设或外推未受影响范围.
