## Project Facts 工程事实

修改前识别真实业务根、feature 根、模块与路由入口、i18n 目录、请求/通知封装、
权限方式和现有构建/验证入口. 读取相关相邻 feature, 区分业务应用、主框架和组件库.
组件事实依次取自目标锁定版本的文档或源码、相邻已用实现、实际可用且版本匹配的知识工具;
不要凭记忆引入属性、图标 key 或新的 UI、请求、状态管理依赖.

工程有同步基座壳时, 识别会被同步覆盖的目录, 将业务代码放到真实业务根.
`src/` 禁写只适用于已证明该目录是同步壳的布局, 不机械推广到所有 Angular 工程.
用户已确认的接口契约不能被相邻旧实现反向改写.

前端调试默认在本地启动目标项目, 将 API 代理到已授权环境. 从实际 package scripts、
serve 配置和代理文件确认开发命令、监听地址、协议、端口、servePath/baseHref 及 API 目标,
不固定使用归档或其他项目的地址. 代理文件中的既有 target 不代表本次目标环境;
需要隧道时核对实际转发关系, 沿用已授权访问方式; 配置、隧道与依赖变更遵循已有授权,
不从访问需求推导额外权限.

区分独立 SPA 与 Host 加载本地 Remote 的调试模式, 以本次页面实际入口选择.
Host 模式还需确认真实 MF 名称、remote 映射、资源前缀和 chunk 加载路径,
不能从仓库名猜测或将环境页面隧道当作本地 dev-server.
例如 EBS/Yak 当前配置分别使用 `/ebs/`、`/backup/`, 后者的 MF 名称是 `backup`;
这些是项目配置示例, 端口、代理和入口仍须现场确认. 浏览器生效验证见
[frontend-testing.md](frontend-testing.md), 不为普通本地联调替换环境 dist.

## Contract And Wiring 契约与接线

- 接口 endpoint、method、请求参数、响应数据位置、字段类型、分页总数、状态枚举、
  权限键和轮询间隔取自实际代码、有效契约或用户确认. 关键事实缺失时先澄清,
  不按 REST 惯例或资源名猜测.
- 按实际架构接通页面落位、模块注册、路由、provider、权限入口和适用 locale.
  新路由不得被参数路由或 wildcard 吞掉; 不强制把所有项目改成同一种模块或懒加载方式.
- 请求和响应模型映射放在既有 service 层, 复用鉴权、租户上下文、错误处理和通知,
  避免组件重复提示或绕过项目封装. snake_case/camelCase 等转换集中处理.
- loading、提交、防重入、失败恢复和订阅清理覆盖真实生命周期.
  按现有模式处理取消请求、组件销毁和轮询停止, 避免离页后继续更新状态.
- 修改共享模块、路由和 locale 时只做必要增量, 保留其他页面和已有改动.
  涉及调用契约变化时按 `project-relationships.md` 核查 API 与后端联动.

Mock 可用于明确约定的演示或阶段性开发, 必须标明接口与业务效果未接通,
不能将按钮存在、假数据展示或提交无实际效果作为真实功能完成.

## Interaction Conventions 交互规范

以下按页面实际能力、当前项目规范和确认范围适用, 不给每个页面强加整套功能:

| 场景 | 检查约定 |
|------|----------|
| 列表与搜索 | 可搜索字段能在展示中解释其含义, 合并字段明确对应关系; 排序、分页和总数与接口语义一致 |
| 手动刷新 | 按项目规范清除过期数据并加载, 区分初次 loading 与后台刷新 |
| 新增、修改、删除 | 区分真/假分页; 修改后更新对应行, 新增/删除后正确更新数据、总数、勾选与页码 |
| 进行中状态 | 仅有明确状态和间隔依据时轮询; 按规范静默刷新, 在终态、离页或资源消失时停止 |
| 操作归属 | 区分页面级、批量和单行操作; 参数与所选对象匹配, 图标位置沿用组件库和项目规范 |
| 权限与禁用 | 按现有规则隐藏或禁用; 适用时说明不可用原因, 同时保持服务端权限校验 |
| 表单与弹窗 | 提交前校验, 提交中防重复; 失败保留输入与弹窗, 成功后再关闭并同步数据 |
| 空态与异常 | 明确无数据、加载、请求失败和恢复入口, 不将接口异常伪装成空列表 |

跨字段联动应处理依赖值变化后的旧选择、校验和提交内容, 不只改变可见控件.
组件、权限、状态或操作形态存在业务歧义时纳入需求确认, 不替用户定义新的业务能力.

## Theme And Language 主题与文案

- 文案进入项目既有 i18n 流程, 补齐所有适用 locale; 沿用已有术语与键命名.
- 需要随语言切换变化的 UI 状态保存文案键, 避免缓存 `translate.instant()` 的旧语言结果.
- 使用项目主题变量与组件语义色, 不硬编码颜色或臆造 Design Token.
- 使用锁定版本支持的图标和 modal 数据传递方式, 不把旧版本 `@Input()` 习惯套到
  已使用 `NZ_MODAL_DATA` 的实现, 也不无条件迁移全部历史组件.

## Optional Tooling 可选工具

实际提供 `es-frontend` 时可查询组件知识、检查工程、生成骨架或文案.
按工具当前 schema 调用, 不把归档中的工具名当成已注册能力.
缺失时使用项目已有代码、组件文档和命令完成等价工作; 找不到关键契约或组件事实时报告缺口,
不自动安装依赖、启动 MCP 或凭其他组件库类比补参数.

`scaffold-page`、`add-i18n` 会写业务代码、共享入口和 locale, 必须限于已确认范围.
归档的 `dryRun` 仅限制骨架落盘, 导入模块仍可能解压临时资产; `verify-page` 也可能写临时
编译配置. 不把它们视为绝对只读. 本 skill 不附带这些脚本或组件库快照.

菜单、许可证提示、子应用默认入口和部署前缀只在明确需求范围内修改,
产品标识不得由目录名推断. 归档 R2C 的检查维度合入现有 Requirement Review / OpenSpec,
不强制重复确认或生成三份平行规格. 实现后的验证使用 [frontend-testing.md](frontend-testing.md).
