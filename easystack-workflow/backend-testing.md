# EasyStack Backend Testing

## Acceptance Basis 验收依据

将已确认行为与实际调用路径对应, 明确目标仓库、Patch 基线、当前修改和被测版本.
开发约束见 [backend-development.md](backend-development.md), 项目边界见
[project-relationships.md](project-relationships.md). 本文件区分仓库检查与实际资源验收,
不将 Mock、单测或状态字段成功当作跨项目业务效果已经验证.

开发任务验证前按 [product-documentation.md](product-documentation.md) 整理并呈现本次完整
测试顺序. 纯测试任务按确认范围整理并呈现顺序, 不因此创建或改写产品文档; 对已有产品文档
仅在已授权范围内同步. 先测被依赖功能, 集中准备共享前置条件并复用仍有效的资源和结果;
前置失败时将依赖项标为阻塞, 不执行或记录为通过. 异常和破坏场景按依赖安排, 必要复验注明
原因, 清理按逆依赖顺序且遵循当前用户授权和下文清理门禁.

先读取目标项目的测试文档、tox/Makefile、依赖和 constraints. 按代价与风险选择
针对性回归、仓库门禁、契约和运行时验证, 无需机械执行全部项目及所有测试层.
安装、服务启动、环境变更和资源操作沿用实际授权, 不为验证擅自修改全局环境.

## Repository Checks 仓库检查

- 缺陷优先建立修复前失败、修复后通过的最小回归; 新行为覆盖主要成功路径及关键
  失败、边界. 并发、超时、重试、恢复和清理按改动风险纳入, 不用镜像实现的断言凑覆盖率.
- 测试参数、状态、异常及外部调用方式应符合真实接口. Mock 适合隔离依赖, 不能
  证明另一仓库的请求/响应或副作用兼容; 关键契约需结合双方实现和适用契约测试核对.
- 使用实际 stestr、测试过滤器和 fixture. 区分单测与项目内 functional 测试的数据库、
  外部服务和权限要求, 不统一换成 pytest 或猜测不存在的测试环境.
- 验证失败后区分本次引入、仓库既有和环境问题; 在授权范围内修复并重跑相关检查,
  不沿用修复前结果, 不顺带修复无关历史问题.

EasyStack OpenStack CI 先读取实际 `tox.ini` 的 envlist、basepython、commands、
constraints 与测试配置, 确认解释器、tox/stestr 版本和现有隔离环境. 若项目使用共享
Miniconda 环境, 发现真实安装位置并激活匹配环境后执行; 不猜测 Python 版本或环境名称.
缺少工具、系统库或环境时报告缺项, 不自动安装或更改全局环境、tox、依赖来制造通过.

确认存在对应入口后, 先执行 `tox -e cover`, 再执行 `tox -e pep8`.
从实际 coverage 输出定位报告, 核对本次 diff 中新增/修改的可执行行是否有 missing
或 partial 分支; 无关历史缺口单列基线. 定向诊断可在已确认的测试环境中使用
`stestr run <实际测试过滤器>` 或 `flake8 <目标文件>`, 不替代最终两个 tox 门禁.
privsep 测试按项目真实 fixture、helper 和权限运行, 不绕过安全机制或直接接触生产设备.

仅测试请求遇到失败时报告证据与修复方向, 不自动改代码. 已有修复授权时最多进行
3 轮修复与重跑, 每次修复后重新从 cover 检查并最终运行 pep8; 同一失败仍未消除、
越出授权或需修改 CI/配置/依赖/共享契约时停止并报告. 缺少 cover/pep8 入口的项目使用
其真实门禁, 如实说明差异, 不强套 Python 流程到 Go/C 项目. CI 结果不授权 Git 交付,
交付统一见 [delivery.md](delivery.md).

| 改动类型 | 从项目实际入口选择验证 |
|----------|------------------------|
| API/SDK/RPC/object | 旧新调用、版本选择与降级、参数/序列化、错误和对象兼容测试 |
| DB/迁移/状态 | 目标数据库的迁移链和历史数据、事务/并发及恢复, 使用项目真实迁移测试 |
| driver/connector | 实际协议、连接属性、设备路径、多路径与断开清理; Mock 之外另记设备验证缺口 |
| Go operator | 当前 Makefile、Go 测试、生成和 CRD/RBAC 检查; reconcile/status/finalizer 及必要的 envtest/integration |
| C/Go 服务 | 当前构建、单测与协议测试入口, 资源释放和异常恢复; 不硬编未知命令或访问生产设备 |
| Helm/Kolla | 当前模板/配置及构建检查, 安装升级和运行态另记; 不以模板渲染代替部署验证 |

## Runtime Preconditions 运行时前提

1. 确认已授权环境、角色/租户、区域、资源范围及相关服务能力. 服务、SDK、driver、
   connector、镜像/包等版本必须能关联本次变更; 无法关联时不以旧部署成功证明新代码.
2. 按行为清单选择 API、CLI、Tempest、项目集成测试或其他受支持入口, 说明它与目标
   功能的关系. 工具缺失不自动安装, 跨仓库源码可读不等于运行环境已具备.
3. 使用本次任务唯一可追踪的资源标识, 预先明确配额、依赖、关联和清理策略.
   复用或修改已有对象必须符合当前用户授权和下文资源保护规则, 不擅自删除已有资源.

有页面或调用方可见变化时连接 [frontend-testing.md](frontend-testing.md), 对齐同一
被测版本和场景. 后端测试与浏览器验收各自保留证据, 不互相冒充已经执行.

需要将本地改动注入环境、重载或更换运行产物时, 按
[runtime-debugging.md](runtime-debugging.md) 核对完整项目基线、环境配置保留、备份、
全部消费副本、生效和整体回滚. 不要求先有故障, 不把一次路径调试当作完整资源回归.

## Functional Path 功能路径

环境具备条件时, 逐条验证关键路径:

`真实请求/操作 -> API/SDK/RPC -> 异步状态 -> 资源/数据实际效果 -> 调用方反馈`

异步返回、HTTP 成功或状态进入处理中都是中间证据. 等待稳定终态, 回读资源和
关联状态, 检查受影响服务的真实业务效果. 不修改测试断言去接受未确认的新语义.

| 场景 | 按实际风险核对 |
|------|----------------|
| 创建、变更、删除 | 对象和租户正确, 关联、配额和最终状态一致, 必要的反向操作可完成 |
| 挂载、迁移、扩容及明确要求的 Backup 恢复 | 按目标语义检查设备、挂载、容量、读写或数据一致性, 不只断言 API/DB 状态 |
| 失败、超时、重试 | 错误可识别, 无重复操作/资源泄漏, 部分成功可恢复, 重试和补偿能收敛 |
| 并发、重启、故障恢复 | 状态和锁按契约恢复, 幂等与清理有效; 涉及 fencing 时验证实际 I/O 隔离 |
| 权限和版本 | 相关角色、跨租户拒绝、混合版本与兼容窗口, 不对无关组合做全量排列 |

仅执行已授权且与改动有关的故障或破坏性验证. 没有安全环境或所需授权时记录该项
未验证, 先完成其余可行检查; 不通过静态阅读宣称设备或故障恢复测试通过.

## Resource Execution 资源执行

本文件可独立执行 Compute、Storage、Network、Image、Security、Bare Metal 及相关服务
测试. Backup 默认排除; 明确要求时先核对实际 API、版本、权限、驱动支持与清理规则,
不得直接套用普通云硬盘用例, 也不因默认排除而拒绝明确的备份需求.

1. 计划准备不访问环境. 将确认行为映射为用例, 写明依赖、共享前置、成功断言、
   负向/边界路径、超时、中止条件、授权的破坏动作、日志要求和清理策略.
2. 使用实际已授权的访问入口及 API/CLI/现有集成测试. 只读确认环境标识、项目/租户、
   区域、服务能力、配额、引用资源状态和权限, 缓存信息复用前重新核实关键项.
3. 记录 run id、用例 id、唯一资源名与真实 UUID 映射. 每个动作保存开始/结束时间、
   实际命令或请求、退出结果、request ID 和终态证据; 中断恢复先回读实际状态,
   不根据对话猜测进度或盲目重放创建操作.
4. 按依赖执行创建、变更、关联/解除和删除等已确认生命周期. 异步操作设置超时并轮询
   稳定终态, 回读关联、配额及实际设备/数据面效果. 失败时阻塞依赖项, 不能手填通过.
5. 每项标注 PASS、FAIL、BLOCKED 或 SKIPPED 及证据/原因. 功能结果先固化,
   日志完整性、耗时和清理状态分别记录, 清理成功不得覆盖原功能失败.
6. 只清理本次创建或用户显式指定的 fixture, 按逆依赖解除关联后删除并回读确认.
   默认 `preserve_on_failure`, 保留失败现场. 删除和破坏性操作必须已有匹配的明确授权;
   未获授权时只列对象、状态、关联、影响和建议顺序, 不为环境整洁越权删除.

Tempest 自身 tox 单测与 live API/scenario 分别记录; 后者需要真实配置与资源权限,
有用例文件不等于已经运行. 资源操作无稳定终态时先回读, 不盲目重试造成重复资源.

## Worker Evidence 执行日志证据

用例预先声明日志为 required、optional 或 none. 内部执行分支、错误处理、日志本身的
断言及功能失败诊断需要 required; 其他按风险选择. required 缺失时明确对应断言未验证,
不能据此声称完整验收; optional 未采集和 none 分别注明原因, 不自动判为功能失败.

记录运行和用例起止时间及 UTC offset. 首个日志窗口从运行开始, 后续从上一用例结束到
本用例结束; 日志与证据保存前不推进游标. 查询前转换为 UTC, 无时区日志先核实服务
时区, 保留原始时间; 无法确认时标记时间顺序未确认.

按真实执行路径优先采集 primary worker, 如实际 compute、volume、网络 worker 或
节点侧 driver, 需要时再查调度和 API; API 日志不能替代 worker 分支证据.
操作前后各记录服务实例清单, Kubernetes 按 Pod UID 取并集, 保留节点、容器、重启计数.
按窗口读取 current 日志, 重启时补 previous; Pod 已删除则尝试历史日志并标明缺口.
使用实际支持的 `kubectl logs` 时间参数, 无结束参数时在采集后按归一化时间过滤.

按 request ID、资源/attachment UUID、源/目标节点及后端关联原文, 保存原始来源与
必要摘要或 hash. 证据状态区分 COMPLETE、PARTIAL、MISSING 和不适用, 空日志不能
证明没有错误. 在线故障、历史日志或注入验证见 [runtime-debugging.md](runtime-debugging.md),
不把完整根因调查作为每次测试前置. 已安装的专用测试 skill 可作可选增强, 本文件不依赖其脚本.
Git 交付统一见 [delivery.md](delivery.md), 不自动提交或上传.

## Evidence And Completion 证据与完成

以确认的每项行为对账, 精简报告:

- 被测仓库/代码与部署版本、实际命令或操作、成功/失败结果及必要终态证据.
- 仓库 CI、契约检查、实际资源测试、前端 E2E、部署验证各自的执行状态.
- 修复后复验结果, 未执行或失败的具体原因、替代检查与剩余风险.
- 新建/复用资源及清理状态, 遗留对象和需要后续授权的动作.

证据脱敏并限于判断所需内容. 无环境时可报告已完成静态或仓库检查, 必须明确保留
运行时缺口; 本次涉及的 Backup、设备、跨项目版本或关键使用路径未核实, 不宣布完整交付.
实际测试结果、失败/阻塞和未验证项均写入交付说明. 开发任务将其同步到本次产品文档并
附文档链接; 纯测试任务仅在已授权范围内同步已有产品文档, 不自动创建或改写文件. 有效
OpenSpec/Plan 按实际实现和验证同步, 计划、勾选和 Archive 不等于测试通过.
