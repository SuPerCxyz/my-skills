# EasyStack Frontend Testing

## Acceptance Basis 验收依据

先从当前有效设计、需求或提交范围确定已确认的变更行为, 再映射到受影响的真实使用路径,
选择必要的静态检查和功能验证. 范围无法确认时记录待确认项,
不从控件文案推断新增业务能力;
仅文案或展示变更验证其实际显示和适用的版本/静态证据, 不把创建资源列为新增验收条件.
本文件提供前端修改后的独立验收流程, 浏览器工具按当前平台实际能力选择.
来源设计维度见 [frontend-design.md](frontend-design.md); 静态通过与运行时成功分别记录.
开发任务验证前按 [product-documentation.md](product-documentation.md) 整理并呈现本次完整
测试顺序. 纯测试任务按确认范围整理并呈现顺序, 不因此创建或改写产品文档; 对已有产品文档
仅在已授权范围内同步. 按依赖和业务生命周期先后执行, 集中准备共享前置条件并复用仍有效的
资源和结果; 前置失败时将依赖项标为阻塞, 不执行或记录为通过. 异常和破坏场景不得提前破坏
后续前提, 必要复验说明原因, 清理按逆依赖顺序且遵循当前用户授权和下文清理门禁.

## Preconditions 验证前提

1. 识别目标仓库、分支、代码版本及当前修改, 从项目规则、package scripts 和已有配置
   找到 lint、类型检查、构建、单测、预览与功能测试入口, 不编造命令或修改全局环境.
2. 默认使用本地 dev-server + API 代理, 按 [frontend-design.md](frontend-design.md) 确认
   独立 SPA 或 Host Remote 入口、本地 URL、代理目标、项目/租户和权限; 沿用已授权运行方式.
   安装依赖、同步基座、部署和启动服务是否可执行, 按当前授权与影响判断.
3. 记录被测源码/构建或部署版本. 本地联调时, 从浏览器 Network 核实实际加载的 bundle、
   Remote 和相关 chunk 来自本次本地开发实例并包含修改. 同时核对代理配置、请求路径与必要服务端证据,
   确认 API 到达目标环境及正确会话/租户, 不以浏览器请求域名相同推断代理去向.
   无法确认版本或代理目标时标明限制, 不用旧部署成功证明新代码有效.
4. 按确认范围准备资源和清理策略, 复用资源须符合当前用户授权与下文资源保护规则.
   不擅自操作或删除环境中已有资源.

页面能打开、隧道可达或 HTTP 200 不能证明本地修改已加载. 检查适用的 remote 映射、
缓存、资源 URL 与 Content-Type, 避免 manifest/JS/chunk 实际返回 SPA HTML.
按既有鉴权流程处理代理后的会话和租户, 不复制凭据或编造登录方式.

仅当用户明确要求环境部署验证时, 才考虑替换环境中的前端构建产物, 并通过
[runtime-debugging.md](runtime-debugging.md) 核对真实静态资源根、版本、
挂载和缓存策略, 再执行已授权的注入、生效检查与回滚. 不默认热更新、固定目录或删 Pod,
临时替换成功也不等于正式发布或 UI 功能验收完成.

## Static Verification 静态验证

按改动风险执行现有 lint、类型/模板检查、相关单测和必要构建.
Angular 模板需由适用的 Angular 编译入口检查, 不能用普通 tsc 的结果代替模板验证.
工程既有失败和本次引入的失败分开记录, 修复后重新执行受影响检查.

实际使用 `es-frontend` 的 `verify-page` 时, 必须读取完整结果:

- 顶层 `ok: true` 可能包含编译跳过或工程既有错误, 不能单独用作编译或验收证据.
- 核对 `errors`、`warnings`、`compile.skipped`、`compile.errors`、`compile.error`、
  `compile.templatesChecked` 和实际命令/退出结果, 按当前返回 schema 解释.
- `templatesChecked: false` 表示模板未验证; 字段缺省本身也不是通过证据,
  应结合实际编译是否执行及结果判断.
- 若只完成 feature 范围编译或存在 `preexisting` 错误, 如实报告范围,
  不将局部静态检查表述为全项目构建成功.

没有该工具时使用项目实际验证入口, 不为调用同名工具自动安装或注册 MCP.
代码存在、组件渲染、Mock 演示和静态规范通过均不能替代下面的功能验收.

## Functional Path 功能路径

环境具备验证条件时, 对本次新增或改变的业务操作完整验证:

`用户操作 -> 请求/事件 -> 状态变化 -> 实际业务效果 -> UI/调用方反馈`

操作成功 toast、弹窗关闭、请求返回或资源名出现仅是中间证据.
异步操作等待稳定终态, 再回读列表、详情或相关页面确认结果;
按业务实际需要验证刷新、重新进入后的状态一致性.

只选择实际改变的行为及有证据的回归影响, 未改变的操作不机械列为本次验收缺口:

| 修改涉及什么 | 验证重点 |
|--------------|----------|
| 页面入口与路由 | 从真实入口可达, 参数/默认路由正确, 模块和 provider 生效 |
| 列表字段、搜索、排序、分页 | 实际请求及响应映射正确, 展示与筛选一致, 总数、页码和勾选合理 |
| 表单或跨字段联动 | 必填与边界值、依赖值清理、防重复提交、失败保留、修正后可再次提交 |
| 创建、编辑、删除或关联操作 | 实际对象和项目正确, 状态/关联真正改变, 页面反映结果及适用的反向操作 |
| 状态与轮询 | 进行中到终态的反馈、失败、资源消失及离页停止, 不只验证计时器注册 |
| 空态、禁用和异常 | 无数据、无权限、请求失败及恢复路径可理解且符合契约 |
| i18n 或主题 | 适用 locale 无缺键, 切换后动态文案同步, 主题变量和语义色正确 |
| 权限与租户 | 相关角色的可见/禁用行为、后端拒绝和项目切换后的数据隔离 |

新增或改变业务行为时覆盖适用的成功、失败、边界与恢复路径.
仅当目标行为确实涉及上述能力时纳入, 不借测试补造额外业务需求.

## Browser Execution 浏览器执行

1. 使用当前平台已可用且获授权的浏览器能力, 如 `agent-browser`、Playwright 或平台
   浏览器工具. 先发现真实命令/接口与连接方式, 复用合法会话并核实 URL、用户与项目,
   不编造 selector、账号或绕过 TLS/鉴权, 不自动安装工具或注册 MCP.
2. 每次交互遵循 Observe -> Act -> Wait -> Verify. 从当前页面观察可访问名称、DOM
   或快照定位真实控件; 填值、勾选和下拉选择后回读. 刷新、导航和重渲染后重新定位,
   不复用过期 ref、行号或猜测坐标. 对话框和向导逐步核实依赖值与校验反馈.
3. 先用短窗口等待资源出现, 再按业务状态轮询终态, 每段设置超时与中止条件.
   菜单打开、toast、弹窗关闭或名称出现都不能记为终态成功; 检查相关请求/事件、
   页面状态与实际业务效果, 并验证适用的刷新/重新进入及反向操作.
4. 独立创建用例使用唯一 run id 和资源名, 保存 UUID 映射. 用户指定现有对象时,
   操作前核实名称、项目、状态和影响. 创建终态未确认先回读页面与后台状态;
   在确认重试安全且授权有效后最多使用新 run id 重试 1 次. 第二次仍未确认则停止,
   记录 `creation_unconfirmed` 和所有可能已创建对象, 不自动清理或反复提交.
5. 按实际需要保存关键截图、console 和 Network 证据, 关联请求、资源和时间,
   去除凭据及用户数据. 后台核对只补充证据, 不以 CLI 成功代替 UI 操作链路成功.

必要后端效果验证按 [backend-testing.md](backend-testing.md), Backup 默认排除,
明确要求时核实支持路径. 后端仓库 CI 不替代前端构建或 UI E2E.
在线调试和离线证据按 [runtime-debugging.md](runtime-debugging.md), 不作为所有 UI
验收的必需前置. 已安装的专用 UI skill 仅作可选增强, 不依赖其他目录或脚本.

清理前必须向用户说明待清理对象、影响和逆依赖顺序并取得明确确认; 已有覆盖这些对象
及动作的明确清理授权可沿用. 未确认时只记录 `cleanup: recommended`, 不主动删除
云主机、浮动 IP、云硬盘、快照等资源, 尤其保留失败或创建结果未确认的现场.
缺少浏览器、服务或环境时列明未执行路径、替代检查和剩余风险, 不将静态检查当作功能通过.
Git 交付统一见 [delivery.md](delivery.md), 测试完成本身不授权提交或上传.

## Results And Completion 结果与完成

报告先用一句话给出实际变更行为及设计、需求或 Diff 依据. 每项确认行为记录执行状态、
被测版本、实际步骤与适用的业务终态证据; 未验证项同样绑定此范围,
不把通用场景清单或未改变的行为列为本次验收缺口.
截图、console 或请求信息只保留判断所需内容并脱敏, 不以截图序列本身判定成功.

报告精简列出:

- 已验证行为、相关命令/结果及关键证据, 包括实际代码来源和 API 目标环境.
- 失败项及其属于本次修改、既有问题还是环境问题, 修复后的复验结果.
- 未验证项、具体原因、替代检查及剩余风险.
- 测试资源与清理状态, 需要后续处理的实际对象.

没有运行环境时可报告静态检查完成, 但必须保留运行时验收缺口.
关键行为或被测版本无法核实时不得宣布完整交付, 也不把计划中的检查写成已执行.
将实际步骤、结果和未验证项写入交付说明. 开发任务同步到本次产品文档并附文档链接;
纯测试任务仅在已授权范围内同步已有产品文档, 不自动创建或改写文件.
