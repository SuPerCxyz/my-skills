# Environment Intake 测试前环境信息采集

执行用例时按以下两个阶段预检。准备操作及账号授权按实际测试范围核对。

## Login And Scope 登录与范围

1. 确定用例来源和本轮纳入、跳过的用例, 以及已有的创建、复用、删除和后台访问授权。
   长耗时用例按 [执行规则](execution.md#long-duration-cases-长耗时用例) 处理。
2. 账号准备：每个环境至少准备**普通用户**和**管理员**两个账号。
   - 普通用户：执行用例、创建资源，默认账号。
   - 管理员：分配配额、类型管理、迁移、权限前置；不替代普通用户的用例步骤。
   - 普通用户配额不足时，先用管理员分配配额并回读，再回到普通用户继续。
   - 记录两个账号的角色、项目和用途；密码不落盘。
3. 根据 [环境模板](environment.template.json) 准备连接信息。通过 Web E2E 的登录流程
   登录或复用授权会话, 按其项目上下文规则核对用户角色、目标项目与域。项目选择使用 `resources.project_name`;
   同名项目按域和项目 UUID 消歧。
4. 密码仅供本次登录使用。必须通过文件传入时使用权限 `0600` 的运行时配置, 结束后移除
   明文凭据。环境文件留存静态参数, 测试新建资源和凭据不得写入报告中的环境摘要。

## Case Resource Checks 逐用例资源预检

从已选用例的步骤、预期和对应原子操作的前置条件列出实际依赖。每项记录用途、来源
(本用例新建、环境提供或明确授权复用)、数量及单件/总容量、所需权限, 以及项目、名称/ID、
当前状态、可用余量和核对时间。新建资源先写明要求, 创建后再回读实际 ID 和状态。

| 用例涉及 | 登录后只读核对 |
|----------|----------------|
| 实例、镜像 | 镜像可用性和启动属性、规格、系统盘大小、可用区、实例/vCPU/内存剩余配额 |
| SSH 或实例内验证 | 可达路径和登录方式、需要的密钥或账号、镜像内校验工具。使用 SSH 私钥时核对指纹与平台密钥对一致 |
| 网络、浮动 IP | 目标网络与子网、可用地址、端口或浮动 IP 配额。涉及绑定或连通性时核对所需网关、安全组和来源范围 |
| 云硬盘、快照、备份 | 目标类型和后端、卷及快照数量和容量余量、来源镜像/卷/快照的身份和可用状态。按用例核对所需加密密钥、备份、多挂载或迁移能力 |
| 服务或故障注入 | 仅核对该用例所依赖的服务。故障注入需明确已授权的目标、时间窗口和恢复方案 |

- 使用当前项目的页面或已授权的只读后台查询核对。批量执行时计算需同时保留的资源量,
  包含前序用例留下的资源, 并在开测前复核剩余配额。暂不能观察的容量或服务状态记录为官方
  界面/API 未提供或当前权限不可见, 不能以页面上存在类型名代替容量证据。
- 只对无法现场核实且影响开测的必需项集中询问。依赖或授权不满足时, 将受影响用例标为
  `blocked` 并写明所需值和实际值, 其余已具备条件的用例可继续。用例本身的关键参数
  缺失或互相矛盾时标为 `case-issues`。规格或资源替代需符合用例语义和既有授权。
- 普通用户权限不足时, 按 [权限升级规则](execution.md#permission-escalation-权限升级)
  处理。需要释放配额时按 [资源管理](execution.md#resource-handling-资源管理) 核对授权和目标。

## Output 输出

- `/tmp/easystack-env.json` 保存平台和静态资源参数。仅填写现场确认且本轮用到的字段。
- 测试目录的 `ENVIRONMENT.md` 记录目标项目、已核对的各用例依赖、核对时间、纳入/
  跳过范围和阻塞原因。
- 开测前按 [结果与证据格式](execution.md#evidence-policy-证据规范) 确认结果根目录和
  截图、录像能力。需要回填 MeterSphere 时核对计划和用例 ID, 并确认已有回填授权。
