## Context

见 proposal.md. 现有 `code-debug.md` 假定 `/opt` 挂载和 Python 启动方式;
用户提供的注入材料记录特定环境的 hostPath 实践, 包含不能直接推广的节点、副本和回滚假设.
修复前快照和隔离用例保留用于复测比较, 不以单次成功宣称普遍可靠.

## Goals / Non-Goals

目标是将已确认行为落实为可执行且能检查的文档规则. 本次不执行任何环境操作,
不安装工具, 不改变已有访问能力和资源测试职责.

## Decisions

- 复用 env-debugging/code-debug.md 作为唯一详细方法来源. 入口文件只负责路由和授权上下文,
  避免独立维护两套注入或交付流程.
- 先发现运行代码、挂载和管理者, 再选择应用支持的 reload、临时覆盖、持久挂载或镜像方法.
  hostPath 是条件化选项; 不把缩容、删 Pod 或固定语言路径当成通用默认操作.
- 验证区分文件到达、实际运行版本与行为结果. 回滚恢复现场记录的原值,
  覆盖已改变的文件、配置、挂载、镜像和调度, 不移除既有覆盖或他人改动.
- CI 仅在已有修复授权内自动修复. 纯测试调用保留只验证范围; CI 不自行执行交付.
- Review 命令先检查写入副作用, 不能以运行后清理缓存声称只读.
- 主 Agent 串行整合公共入口; 复用子 Agent 仅写 code-debug.md. 用用户现有 OpenCode
  全局配置和实际列出的免费模型进行隔离用例验证, 按工具轨迹而非自述判定结果.

## Risks / Trade-offs

- 免费模型可能不遵守提示 -> 保留原始轨迹和逐项断言, 区分文档缺陷与模型执行偏差,
  不用一次通过宣称全面可靠.
- 临时覆盖可能被挂载或控制器遮盖/替换 -> 生效前后核对真实内容、调度范围与管理源.
- hostPath 节点文件不一致或缩容后重调度 -> 覆盖全部可能运行目标, 或明确授权并验证调度约束,
  不以副本数等于一替代节点约束.
- 注入材料中的案例未经本轮在线复验 -> 标明历史来源与条件, 不固化 IP、账号、目录或原副本数.

## Migration Plan

仅更新已确认文档, 保留原文件路径和索引. 检查格式、链接、保护文件摘要与评审差异后复测.
本轮不准备 push, 不触发 share-skills 发布同步; 原有同步规则在以后交付时仍适用.
