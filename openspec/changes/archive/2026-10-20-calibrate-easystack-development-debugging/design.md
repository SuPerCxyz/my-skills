## Context

见 proposal.md. 已定向读取用户的 Cinder 调试笔记、EBS/Yak 的 scripts、serve/proxy/MF 配置,
并经统一环境入口只读校准目标环境. 历史笔记属于另一环境, 不能当作当前挂载事实.
当前抽样发现 Cinder 使用 Python 3.9, Golem 使用 Python 3.6, 部分工作负载无 /opt 挂载,
且 openstack Golem 启动时会将环境 settings.py 复制进项目目录. 这些只作为限定示例.

## Goals / Non-Goals

将五份现有文档的入口、执行单元和验收证据对齐, 保留授权、版本兼容和回滚边界.
不改全局注入工具, 不将其目录合并、单 Deployment 重启或首 Pod 检查包装成完整项目替换.
不改变代码 Review、CI、项目关系或资源测试授权规则.

## Decisions

- 前端在现有工程事实段落发现实际 dev-server、代理与独立 SPA/Host Remote 模式;
  测试要求浏览器本地 bundle/remote 来源及目标环境 API 证据. 单纯打开环境隧道页不足以证明本地修改生效.
- 后端以项目运行包或构建产物为一致更新边界, 使用清单对账新增、修改和删除,
  而不以单文件补丁或 tar 合并作为默认完成标准. 配置、数据和外部依赖保持独立边界.
- 先识别全部实际消费者, 选定授权且兼容的更新批次, 再处理旧挂载和启动复制;
  避免静默扩大远程操作权限或覆盖环境生成设置. 备份和回滚也以完整项目为单元.
- 原生可复用子 Agent 继承本会话能力, 使用一个会话槽位, 仅写 code-debug.md;
  主 Agent 写另外四文档和 OpenSpec, 复核 diff、链接、保护文件哈希并验收.
- 使用用户全局 OpenCode 配置和实际可用免费模型在临时 fixture 中验证流程选择,
  测试只生成方案和读取合成材料, 不连接真实环境或启动服务.

## Risks / Trade-offs

- 整项目源代码与部署版本不匹配: 要求确认 revision、构建和运行时兼容, 不盲复制本地 checkout.
- 环境生成文件位于代码目录: 先记录配置来源、写入顺序与权限, 把保留策略纳入具体变更方案.
- 抽样包定位不代表所有进程加载版本: 明确样本和未验证项, 环境替换与功能回归不在本任务执行范围.
- 模型流程测试不是权限隔离或部署验收: 保留真实调用记录并独立判定, 不用模型自评代替结果.
