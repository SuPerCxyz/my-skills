# Design

## Context

现有 Web E2E skill 包含独立的原子操作返回约定, 也包含用例总览、环境预检、账号准备和执行报告。它已有单次操作、用例和计划入口, 这些任务在迁移后仍需可达。

## Goals / Non-Goals

**Goals**

- Web E2E 单独支持连接、只读探索、UI 操作、终态回读、技术取证和操作库维护。
- 发布测试提供用例发现、审查、编排、调用 E2E、报告和复测闭环, 同时支持单用例。
- 保留已有工作区修改中确立的账号、用例总览、证据和授权规则。

**Non-Goals**

- 运行真实发布测试、实际发布、外部回填、安装 skill 或 Git 交付。
- 重写已有资源域原子操作、修改原子操作返回字段或迁移历史测试报告。

## Decisions

- 以 skill 名称加载执行能力。新 skill 的计划和静态审查可独立进行, Web 执行需要当前会话可发现的 Web E2E skill 和浏览器能力。
- 运行时配置仍使用现有键。发布测试维护完整测试环境模板及账号、项目、配额和用例预检。Web E2E 保留连接文档中的最小配置。
- 发布测试持有原始步骤、预期、授权范围和证据策略。Web E2E 返回已有结果结构、资源身份、最后观察和证据路径。技术取证留在执行层, 报告布局留在发布测试。
- 业务预期由发布测试解释。产品进入预期失败状态时, 该观察可支持用例步骤通过。执行能力或环境限制使用既有阻塞定义。
- 汇总沿用现有格式, 补充版本范围、覆盖和准出阻断项, 复测关联各次运行及证据。

## Risks / Trade-offs

- 文档迁移可能遗漏引用或重复保存规则。检查两个 skill 的内部链接, 仅在原入口保留用例转接说明。
- 独立加载 Web E2E 时可能缺少发布测试 skill。提供明确能力缺口, 保留已授权的独立 UI 操作入口。
- 已有未提交文档包含预检、取证和报告要求。对照原规则逐项检查迁移, 采用定向离线验证。
